# 文档导航

这个目录里有两类文档，混在一起容易迷路：

| 类别 | 目录 | 读者 | 什么时候看 |
| --- | --- | --- | --- |
| **使用类** | [库结构.md](库结构.md)、[metrics.md](metrics.md) | 库的作者、插件的使用者 | 想知道「我的笔记该怎么写」「插件到底怎么打分」 |
| **设计类** | [契约-stage0/](契约-stage0/) | 改插件的人、审方案的人 | 想知道「知识网关为什么长这样」「某个字段为什么这么定」 |

**只想用插件** → 读仓库根目录的 [README.md](../README.md) 就够了，这页是给要动手改的人看的。

## 阅读顺序建议

| 你的目的 | 顺序 |
| --- | --- |
| 第一次用这个插件 | README → [库结构.md](库结构.md) |
| 想知道插件为什么这么打分 | README「检索质量」节 → [metrics.md](metrics.md) → 阶段 1 |
| 要加一个新工具 | 阶段 0 → 阶段 4 → `knowledge-gateway.v1.schema.json` |
| 要改判定逻辑（会拦答案的那种） | 阶段 1（数值判据）→ 阶段 3（支持原因）→ `samples/` |
| 要看这套东西到底行不行 | 阶段 5 → [观察期方案.md](契约-stage0/观察期方案.md) |

## 一条规矩

**这些文档记的是「当时的结论」，不是「永久有效的规则」。** 每份文档末尾都有「已知局限」一节 —— 那是设计者自己写下的边界，比正文更值得读。真要改设计，先看局限那一节，多数坑已经写在纸上了。
