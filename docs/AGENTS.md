# AGENTS.md — 知识库规则

> **这份文件是给 AI 看的操作手册，不是给人看的说明书。**
> 用法：复制到知识库根目录（文件名保持 `AGENTS.md`），把 `<尖括号>` 改成你自己的内容。之后每次让 AI 干活，它先读这个文件，再动手。

---

## 0. 这个库是什么

`<一句话说清装什么、不装什么。例如：装我读过的文章与我的判断；不装日记、待办、临时灵感。>`

**分工**：人负责选资料、定方向、做价值判断；你负责读、编译、链接、记账。**你不替人做价值判断。**

**开始之前先问清楚**：库装什么、给谁看、要不要能分享（涉及脱敏）、有没有不能收录的东西。问不清楚就先按默认策略做，并在 log 里写明是按默认做的。

## 1. 三层结构（第一次建库就照这个建）

| 层 | 位置 | 规矩 |
| --- | --- | --- |
| 原始资料 | `原始资料-raw/` | **只读不可变**，事实来源。你永远不写、不改、不删 |
| 知识层 | `知识层-wiki/` | 你写、你改；人读、人纠 |
| 规则 | `AGENTS.md`（本文件） | 每次会话先读它 |

**库放哪儿**：数据盘（`D:` / `E:` / `F:`），默认 `D:\Markdown-Wiki`。**不要建在工作区所在的盘（通常是 C 盘）**——库是私人资料，不该和工作区、`node_modules`、git 仓库共用同一片事故面。

**第一次建库的六步**：建上面三层目录 → 本文件放到库根 → 在 `知识层-wiki/` 建空的 `index.md`、`log.md`、`总览-overview.md`（各三行就够）→ 让 AI 读一遍本文件复述规则（复述不对就别继续）→ 把人给的资料放进 `原始资料-raw/` → 按 §6.1 摄入第一篇。

## 2. 页面类型与目录

| 类型 | 目录 | 装什么 |
| --- | --- | --- |
| `资料` | `资料-sources/` | 一份原始资料的摘要页（一资料一页） |
| `概念` | `概念-concepts/` | 定义、机制、术语 |
| `实体` | `实体-entities/` | 人、组织、产品、作品、事件 |
| `对比` | `对比-comparisons/` | A vs B |
| `综合` | `综合-syntheses/` | 跨页的判断、演进中的结论 |
| `总览` | `总览-overview.md` | 全库当前认知状态 |

一页只做一件事：负责**定义**、负责**材料**、还是负责**策略**，不混写。混了就拆页。

## 3. 每次会话开场（必做，别跳）

1. 读本文件。
2. 读 `知识层-wiki/总览-overview.md` —— 三十秒建立全局感。
3. 读 `知识层-wiki/index.md` —— 知道有哪些页面。
4. `grep "^## \[" 知识层-wiki/log.md | tail -8` —— 最近发生了什么。
5. 判定这次任务属于 §6 的哪个操作，再动手。

**不要开局把整个库读一遍。** 索引定位，再深入具体页面。

## 4. 命名、别名、双链

- **页面标题一律中文**，完整可独立理解：`检索增强生成.md`，不要 `RAG.md`。
- 英文原名、缩写、旧称全部进 `别名`。别名是英文检索的唯一入口。
- 别名的含义是「这一页也叫这个名字」，不是「这页提过这个词」：
  1. **全库唯一** —— 同一别名只挂一页，挂两页等于让检索随机挑。
  2. 只收同义写法；正文里顺带提一句的概念不当别名。
  3. 摘要页一律 `<主题>·摘要`，把本色名字留给概念页。
- 文件名禁用 `\ / : * ? " < > |`。
- 交叉引用一律 `[[页名]]`，要改显示文本用 `[[页名|显示名]]`。
- **允许先写红链**：重要但还没建页的概念先链出去，红链就是待办清单。
- 一个主题只允许一页。重复时合并到信息更全的那页，另一页写 `> 已合并至 [[xxx]]`。

## 5. Frontmatter

```yaml
---
类型: 概念
别名: [RAG, Retrieval-Augmented Generation]
标签: [llm, rag]
来源数量: 2
状态: 演进中
创建: 2026-11-01
更新: 2026-11-01
---
```

- `类型` 与所在目录一致；`标签` 2–5 个，同一概念只用一种写法；`别名` 见 §4。
- `来源数量`：支撑本页的原始资料份数。**摄入新资料必须重新计数**。
- `状态`：`草稿`（单一来源）→ `演进中`（多源、仍在补）→ `稳定`（已交叉验证）→ `存疑`（有未解决矛盾）。
  另有 `已归档`，那是生命周期（净增量已被后继页吸收），不是成熟度，两者不混着比。
- 升档判据：`来源数量` ≤1 → `草稿`；≥2 未交叉验证 → `演进中`；有独立第二源印证核心结论 → `稳定`；核心结论被挑战 → `存疑`（同时要：总览分歧表加一行 + 页首 `> ⚠️` 行 + 本字段改存疑）。
- 「独立第二源」四条全满足才算：**路径独立**（不是同一份材料的两次转述）、**口径可比**（分母/单位/时间范围一致）、**至少一源一手**、**留痕且无分歧**（逐条写文件名 + 位置 + 该源支持哪句话）。
- `更新` 每次实质修改都刷新；日期一律 `YYYY-MM-DD`。
- 豁免：`index.md` 与 `log.md` 是元文件，不加 frontmatter，体检时别报它们缺字段。

**这些字段为什么值钱**：检索打分里页名最重，其次是别名、标签，正文最弱。同一句话写在正文里可能一分不给，挂成别名就值钱 —— 所以「这个概念还叫什么」比「这个概念提过几次」重要得多。

## 6. 操作

### 6.1 摄入 ingest

触发：人把文件放进 `原始资料-raw/`，或说「摄入」。

1. **读全文**（不是读摘要、不是读文件名）。
   - **容器格式也算资料**：`epub` / `txt` / `pdf` / `srt` / 图片里的文字，先转成文本再读（PDF 先看有没有文字层，没有就逐页渲染后 OCR；字幕按 `MM:SS` 引用）。**别因为「不是 .md」就只登记一个文件名**——那等于没读。
   - 转写产物只新增、不覆盖原件：`<原名>-转写.md` / `<原名>-OCR转写.md` 放回 `原始资料-raw/`，并标「OCR 待核」。
2. **对齐**：跟人过 3–5 条关键要点，确认这次该强调什么；批量时先说明按默认策略处理。
3. **写资料页**：一句话总结、核心要点、关键引文（带位置）、可信度评估（作者/来源/时间/立场）。
   - **引文硬规则：有引文必须有位置；没有位置就不写引文。**
   - 位置写法：`原始资料-raw/<相对路径>.md:<起始行>`；库外素材写 URL + `访问日期`。
   - 拿不准就写成转述并标 `（转述，非逐字）`，不进「关键引文」区块；再拿不准就不写。**不编造、不凑行号。**
4. **整合（关键，别跳）**：遍历已有页面，逐个判断「这份资料是否改变了它」。
   - 新事实 → 补进对应段落并注明来源。
   - 与旧结论冲突 → **不删旧内容**，就地标 `> ⚠️ 已被更新：[[新页]] 认为……`，并在页尾记这次转折。
   - 冲突分三级：**L1** 细节/数据冲突 → 标注 + log，结束；**L2** 核心结论被挑战 → `状态: 存疑` + 总览分歧表加行 + 页首告示；**L3**（L2 且该页入链 ≥5，或人明确要求取证）→ 先写一句可证伪的命题给人确认，再取证。
   - 提到但无页的重要概念 → 建新页，状态 `草稿`（三行也行）。
5. **更新总览**：结论、分歧、空白有变化就改。
6. **记 log**。

**一次只摄入一两篇**。批量灌库最省事，也最容易产出一堆没有判断的空壳页。

### 6.2 查询 query

- 先读 `总览-overview.md` 与 `index.md` 定位，再展开具体页；不要全文扫描。
- **装了 dsh-wiki-notes 插件就先用它**：`wiki_recall` 一次返回命中页、小节与出处，比 grep 快且带打分。零命中时它会给「最接近的几页」，那是换词重搜的线索，不是答案。CLI 等价命令：`node bin/cli.mjs search "关键词" --root <库根>`。
- 回答必须带 `[[页名]]` 引用；涉及具体断言要给 `文件.md:行号`。
- 查不到就说查不到，并说明缺什么资料。**不拿相近的页充数。**

### 6.3 体检 lint

逐项检查并**直接修**，修完给人清单（必修 / 建议）：

1. 矛盾（两页结论冲突且无人标注）
2. 过时（结论被推翻但仍在用旧口径）
3. 孤儿页（无入链、index 里也没有）
4. 红链（被反复提到却没建页 → 建页或改普通文本）
5. 缺失交叉引用（A 明显该提 B）
6. 索引漂移（`index.md` 与实际文件不一致）
7. 薄页（三份资料过去了还只有一句话）
8. 数据空白（明显缺证据的断言 → 指出该找什么资料）
9. 总览过期
10. frontmatter 不合规（缺字段、`来源数量` 与正文不符、日期没更新）
11. 二级信息失同步（正文改了但 index 摘要 / 总览引用 / `状态` 还按旧的写）
12. 引文无位置

**体检也是产出新问题的时候，别只修 bug。** 插件能顶一部分：红链、孤儿、索引漂移、字段缺失；矛盾、过时、薄页还得人加判断。

### 6.4 归档 archive

- 不物理删除任何页。废弃就标 `> ⚠️ 已废弃，合并至 [[xxx]]`，或改 `状态: 已归档`。
- 归档前有歧义先问，别猜。

### 6.5 造工具（库长到手工做不动时）

需要批量检查、批量回写、把某个外部源定期收进来时，让 AI 写脚本。纪律四条：

1. **先只读**：第一版只输出报告，不写文件。
2. **再 `--dry-run`**：要写就先打印将改哪些页。
3. **幂等**：同一份输入跑两次结果一样，否则回写会把库写坏。
4. **改动前先 `git commit`**：让每一次回写都能回滚。

回写类工具（把体检结果、外部清单、错题记录写回页面）最危险：必须带 `--dry-run`、必须能定位到具体页、必须写 log。

## 7. `index.md` 与 `log.md`

- `index.md`：按类型分组，每行 `- [[页名]] — 一句话摘要（N 份资料，更新于 YYYY-MM-DD）`。摘要是人（或一次有判断的提炼）写的，自动生成的空摘要会制造噪音。
- `log.md`：只追加，不修改。`## [YYYY-MM-DD] <类型> | <一句话>`，类型惯例 `init / ingest / query / archive / lint / schema / fix`。
- **每次实质改动都写 log。没记等于没发生。**

## 8. 边界（硬约束）

- 永不修改 `原始资料-raw/` 下的文件。
- 永不物理删除 wiki 页面。
- 不把整篇原文复制进 wiki：摘要 + 引文 + 链回 raw 即可。
- 不替人下价值判断（「这个观点是错的」），只陈述证据与分歧。
- 有歧义先问，别猜。
- 生成任何会改文件的脚本：先只读 / `--dry-run`，改动前先 `git commit`。
- **三种知识状态要分清**：页不存在（说「没建这页」）、概念不存在（说「这段资料里没有」）、存在但不能回答（说清缺什么）。混成一句「不知道」等于把可查的东西变没了。
