# P2 · 把规矩落成文件（整个库里最重要的一步）

**什么时候用**：骨架搭好后，**在你放入第一份资料之前**。
**贴给谁**：同一个 agent，在库根目录。

---

## 提示词

```
现在给这个库写规则文件 AGENTS.md。要求：

1. 我复制了一份模板在 docs/templates/AGENTS.md（或者你按通用骨架写），
   你按我的实际用途改写，把 <尖括号> 里的东西换成具体的。
2. 至少包含六节：三层结构 / 页面类型 / 会话开场 / 命名与字段 / 摄入与体检 / 边界。
3. 会话开场要写成可执行的步骤（读哪几个文件、看 log 的哪几行）。
4. 边界要写成硬约束（永不做什么），不是建议。
5. 篇幅控制在 200 行以内。宁可少而硬，不要多而软——写长了没人读，包括你。

这个库的用途是：<一句话，例如：装我读过的技术文章和我的判断，不装日记>
读者是我自己，我不是程序员，所以每条规则后面用一句话说清为什么。
写完后逐节念给我听，我确认或改。
```

---

## 验收标准

- [ ] `AGENTS.md` 在库根目录，不是 `docs/` 里
- [ ] 六节齐全，会话开场是编号步骤（能照着做）
- [ ] 边界写成「永不……」，不是「尽量不要……」
- [ ] 每条规则有一句「为什么」
- [ ] 全文 ≤ 200 行
- [ ] 你能用自己的话复述其中三条——做不到说明它写的是给机器看的黑话，重写

## 失败怎么办

- **agent 写了一份 800 行的规则**：砍到 200 行以内。规则越长，遵守率越低；剩下的挪进「附录：以后再加」。
- **规则里出现「尽量」「适当」「视情况」**：改成可判定的表述，否则每会话的判定都不一样。
- **你不确定该不该加某条**：先不加。规则是踩过坑才加的，不是想出来的。
