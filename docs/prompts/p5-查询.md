# P5 · 让它回答前先查库

**什么时候用**：任何问库内知识的问题。
**贴给谁**：同一个 agent，或者装好本插件之后的任何会话。

---

## 提示词

```
回答我的问题之前，先查库，不要凭记忆答。

1. 先读 知识层-wiki/总览-overview.md 和 index.md，定位相关页。
2. 再读具体页面。涉及数字、结论、引文的，给出 `文件.md:行号`。
3. 回答里每个结论后面带 [[页名]]。
4. 库里没有就说没有，并告诉我该补什么资料。不要拿相近的页充数、不要用你自己的通用知识假装是库里的。
5. 如果两页结论冲突，把冲突摆出来，不要替我裁决。
6. 如果这个答案值得留下，问我要不要归档成一页（综合-syntheses/）。

问题：<你的问题>
```

## 装了插件之后

插件做了上面第 1–2 步的加速：模型的 `wiki_recall` 一次调用就能拿到「命中页 + 命中小节正文 + 出处」，不用它自己 ls + grep。所以接上插件后，提示词可以简化成：

```
先 wiki_recall 查库再答；引用页名与出处；查不到就说查不到。
```

---

## 验收标准

- [ ] 回答带 `[[页名]]`，不是「根据资料显示」
- [ ] 具体断言带行号或页码
- [ ] 查不到时明说查不到，并给出「该找什么资料」
- [ ] 没有用通用知识冒充库内知识（问它「这条是库里写的还是你想的」，它能说清）

## 失败怎么办

- **它答得很快但没查库**：追问「你读了哪几页？把页名和行号列出来」。列不出就是没查。
- **它引用了不存在的页**（幻觉页名）：让它在回答前先 `ls` 或 `wiki_recall`，并在回答里标注哪些是红链（待建页）。
- **它把相近的页当答案**：这是最危险的失败模式——听起来对。要求它区分「直接回答」和「只是相关」。
