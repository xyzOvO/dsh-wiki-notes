# P6 · 分享前脱敏

**什么时候用**：要把库或这个插件推荐给别人、要把库推到 GitHub、要截图发出去之前。
**贴给谁**：同一个 agent（它比你更清楚自己写过什么）。

---

## 提示词

```
我要把这个库（或这个插件仓库）分享出去。先做一次脱敏检查，不要改，只报告。

扫描这些东西，逐条列出「文件:行号 + 命中的内容」：
1. 真实人名、公司名、项目代号、客户名
2. 本机绝对路径（C:\Users\... / D:\... / /home/...）
3. 邮箱、手机号、账号、token、密钥（含看起来像密钥的长串）
4. 内网地址、私有域名、数据库连接串
5. 未公开的截图、附件、原始资料原文
6. git 历史里出现过的上述内容（`git log -p` 全量扫，不只是当前文件）

报告格式：分「必修」「建议」「可以保留」三栏。
必修 = 一旦泄露就有实际损失；建议 = 暴露了你的私人兴趣但无实际风险。
不要自动改历史，先给我清单。
```

---

## 验收标准

- [ ] 扫的是 `git log -p` 全量历史，不只是工作区
- [ ] 路径类命中都被替换成 `<你的库>` 这样的占位
- [ ] 截图里的真实页名、标签、枢纽页都换成示例（这类最容易被忽略：图比文字诚实）
- [ ] 报告有「可以保留」栏——不是所有私人信息都需要抹掉
- [ ] 你没让它自动改写 git 历史（那是不可逆操作，要单独决定）

## 失败怎么办

- **它说「没发现问题」**：给它具体的 grep 命令让它跑，别让它凭感觉扫。
- **历史里有旧提交泄露**：单独决定要不要 `git filter-repo` 改写；改写会让别人的克隆分叉，先想清楚。
- **截图里带了真实内容**：用示例库重新截图。文字可以改，图里的页名不行。
