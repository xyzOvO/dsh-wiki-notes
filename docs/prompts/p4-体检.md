# P4 · 体检与修复（含「让 agent 给自己造工具」）

**什么时候用**：每积累 10–20 份资料，或一个月一次。
**贴给谁**：同一个 agent，在库根目录。

---

## 提示词（体检）

```
按 AGENTS.md §6.3 给这个库做一次体检，逐项检查并直接修，最后给我清单。

十二项：矛盾 / 过时 / 孤儿页 / 红链 / 缺失交叉引用 / 索引漂移 / 薄页 /
数据空白 / 总览过期 / frontmatter 不合规 / 二级信息失同步 / 引文无位置。

要求：
1. 修之前的改动先 git commit 一次，方便我回滚。
2. 清单分「已修」和「建议」两栏。已修的写一句改了什么。
3. 红链要么建页，要么改成普通文本，不要留着不管——但不要为了消灭红链硬凑三行页。
4. 输出最后的数字：总页数 / 红链数 / 孤儿页数 / 缺字段页数。
```

## 提示词（让它给自己造工具）

规则重复三次以上，就该写成脚本。这时候你要的不是「帮我检查一下」，而是「写个能重跑的东西」：

```
你刚才手工查的那几项（红链、孤儿页、缺字段），写成 工具-tools/check.py。
要求：
1. 只读，不改任何文件。先输出报告，我确认后再加 --fix。
2. 幂等：跑两遍结果一样。
3. 输出格式固定：每行 `问题类型<TAB>文件<TAB>详情`，方便我 grep 和对比。
4. 加一个 --quiet 只打总结（X 个问题）。
5. 写完先用它跑一遍，把它自己的输出贴给我。
```

---

## 验收标准（体检）

- [ ] 体检前有一次 commit（能回滚）
- [ ] 十二项都过了一遍，没过的说明原因，不是静默跳过
- [ ] 「已修」栏每条都能对上具体文件
- [ ] 最后的数字能被插件的「概览」对上（`node bin/cli.mjs overview --root .` 或面板里的页面数量 / 红链数）

## 验收标准（造工具）

- [ ] 脚本默认只读，`--fix` 才写
- [ ] 跑两遍输出一致（幂等）
- [ ] 有一份实测输出贴给你，不是「应该能跑」
- [ ] 你能看懂它判定的标准（不然它报的问题你没法判断真假）

## 失败怎么办

- **它说「已修复全部红链」但库里多了二十个三行页**：回滚。红链不值得用垃圾页填。
- **脚本第一次跑就把库改了**：立刻 `git checkout .`。纪律是「先只读，报告给我看」。
- **它报「没有问题」但你明明见过红链**：让它把检查项逐条打印匹配逻辑，通常是正则漏了 `[[页名|显示名]]` 这种写法。
