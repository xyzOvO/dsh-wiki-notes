# 使用指南：从一个空目录到能用的知识库

> EN: A hands-on guide: from an empty folder to a knowledge base an AI can actually use — plus how to keep it honest.

这份指南写给**没用过知识库、也不打算学编程**的人。走完前五节，你会有一个能被 AI 检索、能自己长大的库；第六节开始它才和本插件发生关系。

**为什么值得花这一小时**：你问 AI 一个问题，它从原始资料里现翻一遍，答完什么都不留——下次问同一个问题，它又翻一遍，还可能给出不一样的答案。让 AI 维护一个持久化的 wiki，知识只编译一次，之后每次都在上一次的基础上加。这一小时的代价，换的是「你的知识开始复利」。

---

## 0. 先分清：谁负责什么

> EN: Who does what: you pick and judge, the agent reads and writes, the plugin reads.

新手最常见的误解是「装了插件，它就会帮我整理笔记」。不会，也不该会。三方分工是这样的：

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| **你** | 选资料、定方向、判断对错、决定什么值得留下 | 不手写摘要、不手动建链 |
| **AI（agent）** | 读全文、写页面、建链接、记日志、体检修复 | 不替你判断「这个观点对不对」、不改你的原始资料 |
| **本插件** | **只读**：检索页面、读一页正文、给总览、核验回答 | 不建库、不整理、不写回、不联网 |

一句话：**插件是这套规矩的读取端，不是维护端。** 维护靠 agent + 你写下的规则。想清楚这一点，后面每条技巧才不会被误读成「它会自动做」。

## 1. 成品长什么样

> EN: What the finished thing looks like — three layers, six page types, three meta files.

```
你的库/
├── 原始资料-raw/            ← 你丢进来的东西，只读、永不改
│   └── assets/              图片与附件
├── 知识层-wiki/            ← AI 写的地方
│   ├── 总览-overview.md     全库当前认知状态（开场先读它）
│   ├── index.md             内容索引（按类型列全部页面 + 一句话摘要）
│   ├── log.md               时间线，只追加
│   ├── 资料-sources/        一份资料一页摘要
│   ├── 概念-concepts/       定义、机制、术语
│   ├── 实体-entities/       人、组织、产品、作品、事件
│   ├── 对比-comparisons/    A vs B
│   ├── 综合-syntheses/      跨页判断、归档的好答案
│   └── _模板-templates/     页面骨架
└── AGENTS.md                ← 规则，AI 每次开工先读它
```

**三层为什么这么分**：原始资料是不可变的事实来源（追源断不了）；wiki 是可以重写、可以变薄的压缩层；`AGENTS.md` 是让 AI 每次都守同一套纪律的东西。少任何一层都会塌——没有 raw，引文无法核对；没有 wiki，每次都要重读原文；没有 AGENTS，AI 每次的规矩都不一样。

**关于「一个目录 + 一堆 .md 也能用」**：确实能用，插件第 0 层就支持。但你很快会撞上两件事：① 你自己找不到东西——几十页平铺，没有索引、没有类型、没有时间线；② AI 每次都要把整个库读一遍才知道有什么。**推荐按上面的结构起步**，成本是多建六个目录，收益是这套库半年后还讲道理。

**目录名为什么是「中文-英文」双语**：中文给你看，英文给脚本留锚点。纯中文目录在多数工具里没问题，但一旦要写脚本做统计，英文段能省掉一堆编码麻烦。

## 2. 第一步：让 agent 搭骨架

> EN: Step 1 — let the agent scaffold the folders and meta files. Prompt: P1.

在你要放库的地方建一个空目录，用编辑器或文件管理器打开它，然后把 **P1 提示词**（[`docs/prompts/p1-搭骨架.md`](prompts/p1-搭骨架.md)）贴给 AI。

要点只有三条：

1. **先只要骨架，不许创作内容。** 库的第一批内容必须是你自己的资料，示例内容会污染检索和你的判断。
2. **验收看目录树，不看它说了什么。** 六个类型目录 + 三个元文件 + 模板，一个都不能少。
3. **空目录 Obsidian 不显示**，让它在每个目录里放个占位文件。

搭完之后你应该能打开 Obsidian（或任何 Markdown 编辑器）看到这棵树。

---

## 3. 第二步：把规矩落成文件

> EN: Step 2 — write the rules down as `AGENTS.md`. Prompt: P2.

这一步是整个库里最重要的一步，也是最容易被跳过的一步。

**为什么必须落成文件**：你把规矩说在对话里，明天开新会话它就没了；AI 会按「它觉得合理的方式」重建库，两三次之后库就散了。把规矩写进 `AGENTS.md` 放在库根目录，agent 工具会在开场自动读到它——这跟人交接工作要留 SOP 是一个道理。

**用我们的模板**：[`docs/templates/AGENTS.md`](templates/AGENTS.md) 是一份 200 行的通用骨架，六节：三层结构 / 页面类型 / 会话开场 / 命名与字段 / 摄入与体检 / 边界。复制到你的库根目录，把 `<尖括号>` 改成你自己的，再让 agent 帮你补细节（**P2 提示词**）。

模板里那几条最值得保留的：

- **会话开场四步**：读规则 → 读总览 → 读索引 → 看日志尾巴。这是「AI 如何接管一个陌生库」的仪式，没有它每次都靠猜。
- **别名的三条硬规则**：全库唯一；只收「这页也叫这个名字」的写法；摘要页一律 `X·摘要`。别名是英文检索的唯一入口，写错了等于永远搜不到。
- **状态四档 + 升档判据**：`草稿 → 演进中 → 稳定 → 存疑`，另加 `已归档`（生命周期，不是成熟度）。绝大多数人只定义了档位，没定义「怎么升」——于是所有页永远停在草稿。
- **边界六条**：不改 raw、不物理删除、改动必记日志、不复制原文、不替人下判断、有歧义先问。

---

## 4. 第三步：摄入（库长大的方式）

> EN: Step 3 — ingest, one or two sources at a time. Prompt: P3.

把文章、PDF、字幕、会议记录丢进 `原始资料-raw/`，然后贴 **P3 提示词**。

**五步，第四步是分水岭**：

1. **读全文**——不是读文件名、不是读摘要。
2. **对齐**——它先给你 3–5 条要点，你确认这次该强调什么。
3. **写资料页**——一句话总结 / 核心要点 / 关键引文 / 可信度评估。
4. **整合**——逐个检查已有页面：这份资料**改变了哪一页**？这是 wiki 与「一堆摘要」的全部区别。跳过这步，你得到的是平行摘要，不是知识网。
5. **更新总览、记日志**。

两条硬规则，建议原样抄进你的 `AGENTS.md`：

- **有引文必须有位置，没有位置就不写引文。** 位置 = `原始资料-raw/<文件>.md:<行号>`；拿不到就写成「转述（非逐字）」，再拿不到就不写。不编造、不凑行号——引文是全链路里**唯一能被机器核对**的内容。
- **冲突不删旧内容**，就地标 `> ⚠️ 已被更新：[[新页]] 认为……`。矛盾比一致有价值，那是这个库比你脑子强的地方。

顺便说一句节奏：**一次一两篇，别一次丢五十篇**。批量省事，但长出来的是一堆平行摘要。

---

## 5. 第四步：体检

> EN: Step 4 — lint, fix, and look at the numbers change. Prompt: P4.

每积累 10–20 份资料，或者一个月一次，贴 **P4 提示词** 让它体检。十二项：矛盾 / 过时 / 孤儿页 / 红链 / 缺失交叉引用 / 索引漂移 / 薄页 / 数据空白 / 总览过期 / frontmatter 不合规 / 二级信息失同步 / 引文无位置。

三件事要盯住：

1. **体检前先 commit**（`git commit -am 体检前`），不然它改坏了你回不去。
2. **红链不要硬凑页**。红链是「这里引用了一个库里没有的判断」，是待办清单，不是错误；为了消灭红链建二十个三行页，比留着红链糟得多。
3. **体检之后去插件里看数字**（见下一节）。AI 说「已修复」，插件说「红链还有 3 个」——信插件，那是它自己数出来的。

**让它给自己造工具**：同一件事查了三次以上，就该写成脚本。P4 里附了「造工具」的提示词，纪律是**默认只读、幂等、`--fix` 才写**。这是唯一能让库在你睡觉时还保持整洁的办法。

## 6. 接上插件

> EN: Step 5 — install the plugin, point it at the library, verify once., point it at the library, verify once.

到这一步库已经能自己长了。现在让它变快：

```bash
# 1. 装（在 DSH 里）
dsh plugin add dsh-wiki-notes

# 2. 指路径：设置 → 知识库 → 库根目录，填你的库绝对路径
#    或者命令行验证一次
node bin/cli.mjs overview --root "你的库路径"
node bin/cli.mjs search 关键词 --root "你的库路径"
```

**三处入口，同一份数据**：左侧栏那本书（完整面板）、设置 → 知识库（配置）、右侧栏「知识库」页签（随手查）。

**验收只要一次**：在会话里问一句和库有关的话，看模型是不是调了 `wiki_recall`、返回里有没有页名与 `文件.md:行号`。有，就通了。

插件**做了什么**：一次调用拿到「命中的页 + 命中小节正文 + 出处 + 为什么命中」；零命中时给最接近的 3 页（而不是空白）；能读任意一页；能给全库总览；能核验一段回答里有没有编造引文。

插件**不做什么**（重要）：不写你的笔记、不整理、不联网、不把内容发出去。它是只读的——这一点写在代码里，不是可配置项。

## 7. 日常使用与技巧

> EN: Day-to-day usage, and the tricks worth knowing.

### 7.1 三段典型对话

```
你：RAG 和长上下文这两条路线的分歧到底在哪，库里现有的资料怎么看？
（它会先查库，答完带 [[页名]] 与行号；满意的答案让它归档成一页）

你：帮我把《某篇文章》摄入，重点讲清它跟现有 wiki 的分歧。
（走 §4 五步；它应该告诉你哪几页被改了）

你：巡检一下，修完给我清单，顺带告诉我该找什么资料。
（走 §5 十二项）
```

### 7.2 插件侧的三件事

- **红链在哪里看**：面板「概览 → 内容问题」看总数，「探索 → 关系 → 最该先补的页」看具体缺哪几页。这是你「下一步该建什么页」的清单。
- **为什么不替你写**：只读是设计。自动写回意味着它能在你不知情时改你的库——那种方便，代价是你不再知道库里什么是真的。
- **要回写就让 agent 做**：插件给出证据（哪页缺、缺什么），agent 拿文件工具去改，改完刷新面板看数字变化。这条链里每一步你都能看见。

### 7.3 库侧的三个习惯

- **素材自动收集**：浏览器剪藏（Obsidian Web Clipper / 各类 Readwise 类工具）直接落进 `原始资料-raw/`，图片跟着下载到 `assets/`。收集和编译分开——收集要无脑，编译要有判断。
- **两段式**：`raw` 只进不改；`wiki` 反复重写。永远不要在 raw 上「顺手改一句」，那是你唯一的事实来源。
- **日志当记忆**：`log.md` 是给「三个月后的你」看的。每次摄入、体检、改规则都记一条，回头能看见库是怎么长歪又怎么救回来的。

## 8. 分享前脱敏

> EN: Before you share: sanitize. Prompt: P6.

库是私密的，插件是可以分享的。分享之前贴 **P6 提示词** 扫一遍：真实人名/公司、本机绝对路径、邮箱与密钥、内网地址、未公开原文、**截图里的真实页名**。

最后一条最容易被忽略：文字可以改，图比文字诚实。要发截图就用示例库（本仓库 `examples/` 里那两个）重新截。

## 附录 B · 插件认的字段与文件（规格速查）

> EN: The exact fields and files the plugin reads. Everything here is optional; missing a field only disables that scoring path.

**第 0 层 · 最小可用**：一个目录，里面放 `.md`。插件跳过 `.` 与 `_` 开头的目录、`index.md`、`log.md`；单页超过 512 KB 只记元数据不读正文。

**第 1 层 · frontmatter 七字段**：

| 字段 | 取值 | 作用 | 缺失后果 |
| --- | --- | --- | --- |
| `类型` | 概念 / 实体 / 对比 / 综合 / 资料 | 类型筛选；同分排序（综合 > 概念/实体/对比 > 资料） | 筛选失效，排序退化 |
| `状态` | 草稿 / 演进中 / 稳定 / 存疑 / 已归档 | 状态筛选 | 筛选失效 |
| `标签` | `[a, b]`（中英文逗号都认） | 标签筛选；命中 **+25 分** | 标签通道失效 |
| `别名` | `[a, b]` | 别名命中 **+50 分**（中英文、缩写、旧称都能搜到） | 缩写永远搜不到 |
| `来源数量` | 数字 | 证据强度的唯一可靠代理 | 不显示证据强度 |
| `创建` / `更新` | `YYYY-MM-DD` | 同分时新的在前 | 排序退化为名字序 |

资料页另建议 `标题` / `作者` / `来源` / `覆盖文件`。英文写法 `title/type/tags/aliases/status/created/updated/sources` 也认。**别自己发明「可信档」这类字段**，它不会被读。

**第 2 层 · `index.md`**：每行 `- [[页名]] — 一句话摘要（N 份资料，更新于 YYYY-MM-DD）`。摘要只在其它通道全为 0 时给 8 分（只补漏、不抢位），但 `overview` 模式会原样显示它——这是「一次调用就能直接回答」的关键。

**第 3 层 · `log.md`**：只追加，`## [YYYY-MM-DD] <类型> | <一句话>`，`overview` 显示最近 5 条。

**第 4 层 · `总览-overview.md`**（或 `总览.md`）：`overview` 模式整段返回它的正文。建议四块：这个库在讲什么 / 各页成熟度 / 未裁决的分歧 / 待补缺口。

**双链**：`[[页名]]` / `[[页名|显示名]]`。指向不存在的页 = 红链（信号，不是错误），`overview` 会汇总，面板「关系」页签会列出。

**五分钟最快验证**：

```bash
mkdir my-wiki && cd my-wiki && mkdir 概念-concepts
printf -- '---\n类型: 概念\n状态: 草稿\n标签: [示例]\n别名: []\n来源数量: 1\n创建: 2026-11-02\n更新: 2026-11-02\n---\n\n# 示例页\n\n## 它是什么\n\n一句话说清这个概念。\n' > 概念-concepts/示例页.md
WIKI_ROOT="$PWD" node bin/cli.mjs search 示例
```

更完整的可跑样例：`examples/demo-wiki/`（10 页，带索引/日志/双链/红链/别名）与 `examples/flat-wiki/`（8 页，平铺零 frontmatter，证明第 0 层真能用）。

## 附录 C · 常见失败

> EN: The five ways this usually goes wrong.

| 症状 | 真正的原因 | 怎么办 |
| --- | --- | --- |
| 库建好了，但搜什么都搜不到 | 页名太泛（`笔记1.md`）、没有别名、正文是摘抄 | 改页名为完整主题名；补 `别名`；让 agent 重写摘要 |
| 搜得到，但答得不对 | 页里只有材料没有结论；或两个源冲突没人标 | 体检第 1、7 项；让 agent 把结论写进页首 |
| 库越写越乱 | 跳过「整合」这一步，长出一堆平行摘要 | 回到 §4 第 4 步；合并重复页，保留信息更全的那个 |
| agent 每次都要重新认识这个库 | 没有 `AGENTS.md`，或规则太长它读不完 | 写 200 行以内的 `AGENTS.md`，开场四步固定下来 |
| 所有页永远停在「草稿」 | 只定了档位，没定升档判据 | 抄模板里的升档四条：来源数量 + 独立第二源 + 留痕 + 无分歧 |
