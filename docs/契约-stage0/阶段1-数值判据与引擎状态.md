## 2 判据设计（与拍板逐条对应）

### 2.1 五维

`_scope_of(text)` 从文字里抽三组适用范围：`region`（地域）、`variant`（口径类型）、`period`（年份）。数值侧另两维由 `_METRIC_PATTERNS` 承担：数值/单位（`normalize()` 统一时长到分钟）与指标（`duration`/`count`/`score`/`words`）。

### 2.2 `compare_scope` 的三条语义

1. **只有两侧都标了某维度，该维度才提供判据**——一侧缺不自动算匹配。
2. 都有值且相交 → 相容；都有值不相交 → `mismatch`。
3. 所有维度都不提供判据 → `unknown`，绝不默认 `match`。

### 2.3 补一条拍板没写、但实测必须有的规则：`scope_gaps`

主张说「2023 年配 6 个分片」，证据只写「星港 4 分片」，`compare_scope` 会给 `match`（年份一侧缺）。若照此比较就会得出 `contradicted`——把「证据没说」当成「证据反对」。

所以加 `scope_gaps(claim_scope, ev_scope)`：主张限定了、证据没写的维度。命中时不进 `matched`，进 `partial`，最终判 `unverifiable`：

```
证据与主张的适用范围有一侧未标注，不能视为匹配（证据：星港·区域口径）
```

这正是拍板里「未标注 ≠ 适用于所有情况」的直接落地。

### 2.4 四态判定顺序（`judge_claim`）

```
无同指标证据            → unverifiable
有 matched 且数值全等    → supported
有 matched 且数值不等    → contradicted
只有 partial（范围缺口） → unverifiable
只有 mismatched         → scope_mismatch
只剩 unknown            → unverifiable
```

`scope_mismatch` 与 `contradicted` 分开输出，回答里永不出现「星港一定不是 5 分片」这种话。

### 2.5 证据侧的范围归属（踩过的真 bug）

`build_evidence_pool()` 里，一条证据的范围**以数字所在那句话为准**；那句话自己没标范围时，才退回页面标题。

原因：「星港缓存配置基线」页里有一句「统一口径缓存策略 5 分片、180 秒」，若按标题取范围，这句就变成星港口径，直接把统一口径证据洗成星港证据——正是拍板要防的错配。

### 2.6 违规与提示分开

- `contradicted` / `scope_mismatch` → `violations`，`type = unsupported_numeric_claim`，带 `status`
- `unverifiable` → `notices`；**仅当答复没有任何复核措辞**（`REVIEW_WORDS`）时才升为 violation。答复自己写了「需复核」，就不再重复报警
- 判据内部异常 → `numeric.check_failed` / `internal_error`，可见，不静默通过

## 3 F1：引擎状态显式化

`run_search_py()` / `run_plugin()` 的异常分支带 `status ∈ timeout|error`；`build()` 记 `engine_states[{engine, query_id, status, candidates, error}]`，`status` 区分 `ok` / `empty`（通了但零命中）/ `error` / `timeout`。输出新增 `engines` 聚合与 `pipeline.degraded` / `degraded_sources`。

实测：把 `cb.PLUGIN` 指向不存在目录 → 插件侧 `error` + `degraded=true`，`search.py` 仍产出 8 条证据，`support` 保持 `partial` 没跌成 `insufficient`，错误原因 `[WinError 267] 目录名称无效。` 完整保留在输出里。

## 6 已知局限（不要当成已解决）

1. **口径别名覆盖不全**：`星港缓存策略` 这种写法只抽到地域，抽不到 `区域口径`。后果是统一口径证据里的「统一口径 30%」与「星港冷数据 30%」只能判 `unverifiable`（保守，不放行），而不是更准确的 `scope_mismatch`。
2. **中文数字支持到千位**，且只认「一二三四五六七八九十百零两」；「二十余」「十几」这类模糊量词抽不出，属未覆盖。
3. **不做跨句推理**：只比较单个分句里的数值主张，句中指代（「这一说法」「上述数字」）不追踪。
4. **`unverifiable` 会升 violation**：答复没写复核措辞时，不确定的数字主张也算违规。这是刻意选择——把不确定当定论说出来，就该被标；如果将来觉得太严，改 `REVIEW_WORDS` 触发条件即可。
